# SiteWatcher Web Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a secure, complete one-owner web alternative to the Telegram bot.

**Architecture:** FastAPI/Jinja2 server-rendered UI in an optional Compose web service; reuse SQLite storage and Dispatcher. Shared YAML global config is validated and written atomically, with bot restart indicated.

**Tech Stack:** Python 3.12+, FastAPI, Starlette sessions, Jinja2, Uvicorn, stdlib scrypt, SQLite, pytest/TestClient, local CSS and vanilla JS.

**Spec:** `docs/superpowers/specs/2026-10-01-web-panel-design.md`

## Global Constraints

- Preserve bot behavior, checks, multi-user data isolation, and existing Docker bot-only startup.
- Web access is one configured Telegram owner only; no default credentials or public JSON API.
- All mutations use POST plus CSRF; all rendered untrusted text is escaped.
- UI English, responsive, light/dark, 45-second overview refresh.
- Use no npm build or CDN.

## Review Focus

- A second Telegram owner's domain must never appear or be mutated through web routes.
- Invalid or cross-origin POST must not mutate data.
- Invalid YAML must not replace a valid config file.
- Manual checks must not recreate a deleted domain or silently run an unknown domain.
- History period filtering must work with SQLite's `YYYY-MM-DD HH:MM:SS` timestamps.
