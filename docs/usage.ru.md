# Руководство SiteWatcher

[← Коротко о программе](../README.ru.md) · **Русский** · [English](usage.en.md)

SiteWatcher следит за сайтами и показывает результаты в закрытой веб-панели. Уведомления в Telegram и публичная страница состояния подключаются по желанию. Веб-процесс и фоновый worker работают с одной SQLite: отдельный сервер базы данных не нужен.

Доступные проверки: HTTP-ответ и скорость загрузки, сертификат TLS, ping, ключевые слова и признаки подмены страницы, реестр РКН, смена IP, IP-блоклисты, TCP-порты, WHOIS/RDAP и репутация в VirusTotal. Затратные проверки выключены по умолчанию или запускаются реже. Настройки и история привязаны к владельцу.

## Быстрый запуск через Docker

Нужны Docker и плагин Compose. В каталоге проекта выполните:

```bash
docker compose run --rm --build setup
docker compose up -d
```

Создайте имя пользователя и пароль, затем откройте **http://127.0.0.1:8080**. Можно сразу добавлять домены: `.env`, Telegram и редактирование YAML для этого не требуются. Если порт занят, задайте `SITEWATCHER_PORT=8081` при запуске Compose.

Контейнеры работают без root. База, ключ веб-панели и сохранённое подключение Telegram находятся в томе `sitewatcher-data` и сохраняются при перезапуске. Порт доступен только с локальной машины.

```bash
# Просмотр журналов
docker compose logs -f web worker

# Остановка с сохранением данных
docker compose down

# Разовая проверка без добавления домена
docker compose run --rm web sitewatcher scan example.com --only http_basic,tls_cert
```

Не добавляйте `-v` к команде остановки, если нужно сохранить данные. Перед обновлением сделайте резервную копию. В контейнере используется база `/data/sitewatcher.db`.

После подключения Telegram в настройках можно включить команды бота:

```bash
docker compose --profile telegram up -d
```

Этот бот запускается с `--no-scheduler`: расписанием продолжает управлять worker. Для закрытого бота передайте `TELEGRAM_ALLOWED_USER_IDS` через локальный Compose override.

## Запуск из Python

Поддерживаются Python 3.12–3.14 и SQLite 3.35+ с JSON1.

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e .
sitewatcher setup
sitewatcher web
```

Во втором терминале из того же каталога:

```bash
. .venv/bin/activate
sitewatcher worker
```

Откройте **http://127.0.0.1:8080**. Оба процесса должны использовать одну базу и одинаковую конфигурацию.

По умолчанию база — `./sitewatcher.db`. Для постоянной установки задайте абсолютный `DATABASE_PATH`; его каталог должен существовать и быть доступен для записи. Рядом создаётся индекс РКН `z_i_index.db`.

Встроенной конфигурации достаточно для начала. Для изменения общих параметров скопируйте [пример YAML](../sitewatcher/data/config.yaml.example) и передавайте `--config config.yaml` командам. Явно указанный отсутствующий файл, неизвестные ключи, неверные пороги и некорректные списки доступа отклоняются при запуске. Значение `0` сохраняет свой смысл и не заменяется значением по умолчанию.

## Веб-панель

### Добавить первый сайт

1. Нажмите **«Добавить домен»** — значок **+** вверху.
2. Введите адрес, например `example.com`, `http://example.com` или `example.com/catalog/`. Без протокола выбирается HTTPS.
3. Оставьте предложенные настройки или задайте свой интервал и нажмите **«Добавить домен»**.

Когда фоновая проверка закончится, появится результат. Чтобы не ждать расписания, нажмите **«Проверить сейчас»** рядом с сайтом. Компьютер или сервер с SiteWatcher должен оставаться включённым.

| Что написано | Что это значит |
| --- | --- |
| Успешно | Проверка выполнена без обнаруженной проблемы. |
| Предупреждение | Есть причина обратить внимание: например, медленный ответ или недоступные данные. Наведите на ярлык, чтобы узнать подробности. |
| Критическая ошибка | Одна из проверок обнаружила серьёзную проблему. Подсказка и история покажут какую. |
| Нет данных | Пока нельзя сделать вывод. Например, внешний сервис не ответил или ещё нет результатов. |
| На паузе | Автоматические проверки остановлены; разовую можно запустить вручную. |

### Домены и история

Нажатие на имя домена, свободную часть строки или стрелку раскрывает последние проверки и график HTTP. Сначала показан график на всю ширину, ниже — компактный список проверок в две колонки, на телефоне — в одну. В строке показаны название и статус; пояснение и время отдельного результата доступны по наведению. Можно открыть несколько доменов для сравнения. Ссылка «Полная история» находится внутри раскрытия; без JavaScript имя домена ведёт в полную историю; избранное, перестановка, редактирование, ручная проверка и пауза доступны без раскрытия. [Пример раскрытия](screenshots/overview-inline-details.png).

Сводка состояния отделена линиями справа от логотипа SiteWatcher и содержит строку «Обновлено … назад» для последнего сохранённого результата проверки. Точная дата и время доступны по наведению. Период истории расположен в заголовке таблицы справа от «Последняя проверка». На узких экранах сводка переносится под логотип. Примеры: [компьютер](screenshots/overview-compact-header-desktop.png), [телефон](screenshots/overview-compact-header-mobile.png).

- Добавляйте до 50 доменов через запятую с общими настройками. Весь список проверяется до сохранения; при ошибке или дубликате он не сохраняется.
- Нажмите звёздочку, чтобы поднять домен в избранное. Порядок можно менять перетаскиванием; избранные всегда остаются сверху.
- Наведите курсор на ярлык критической ошибки или предупреждения либо перейдите к нему клавишей Tab: появятся причины и время каждой проверки.
- В карточке домена доступны история за сутки, 7 и 30 дней, график времени ответа и фильтры последних проверок. Точки графика показывают время и значение при наведении или фокусе.
- Поиск расположен рядом с заголовком «Домен», а заголовок «Статус» открывает список фильтров. Переключатель 24 ч / 7 дн. / 30 дн. находится в верхней сводке рядом со временем последней проверки. Примеры: [компьютер](screenshots/header-filters-desktop.png), [телефон](screenshots/header-filters-mobile.png). Поиск и фильтры применяются сразу. Диапазон дат включает оба выбранных дня в часовом поясе панели; история показывает до 100 подходящих записей. Фильтры истории не меняют период графика.

Кнопка с сигналом в верхней панели открывает **«Проверки в реальном времени»**: тёмную сцену с сервером SiteWatcher, доменами и светящимися импульсами в духе PONG. Запрос летит к домену, ждёт результат и возвращается с его цветом. По умолчанию путь занимает четыре секунды в каждую сторону; скорость, пауза, повтор последних событий и полноэкранный режим управляют только изображением. Сам мониторинг работает в обычном темпе. Сохранённые события явно помечены как повтор.

Под сценой находится небольшая прокручиваемая консоль: время, понятное название проверки, домен, результат и реальная длительность. Она обновляется каждые две секунды, в том числе на паузе анимации. При чтении старых строк автопрокрутка останавливается; кнопка возвращает к последним событиям. Карта показывает все сохранённые домены, включая сайты без недавних событий. Точки сохраняют своё место; цвет отражает последний сохранённый результат отдельной проверки, а наведение показывает домен, название проверки и состояние. Активный сайт разворачивается в карточку, после возвращения ответа задерживается на пару секунд и сворачивается обратно. Нажатие на точку или карточку закрепляет один домен; повторное нажатие или крестик открепляет его. Закрепление не запускает проверку. Сцена допускает до шести раскрытых карточек и трёх одновременных сигналов; на узком экране — до четырёх карточек и двух новых сигналов. Большая карта имеет собственную прокрутку, журнал хранит до 100 строк. Всплески событий не создают бесконечную очередь анимации.

Включение запоминается в браузере. Выключение блока и скрытие вкладки прекращают опрос; системное предпочтение уменьшенного движения оставляет статичную схему и консоль. Пока сцена открыта, автообновление не перезагружает всю страницу. Открытие сцены не запускает проверки: она показывает события мониторинга, а не отдельные сетевые пакеты. [Обычный вид](screenshots/signal-room-desktop.png), [полный экран](screenshots/signal-room-expanded.png), [телефон](screenshots/signal-room-mobile.png).

Для выбранного домена доступен **Сетевой маршрут**: нажмите точку домена на карте и **Запросить маршрут**. Worker выполнит UDP-traceroute и далее будет обновлять его раз в час; обновления можно отключить. **Показать маршрут** разворачивает цепочку реальных узлов с IP, PTR-именами и временем ответа. Весь маршрут помещается в одной сцене: узлы показаны точками, сигналы проходят через них. На телефоне цепочка укладывается в несколько рядов. В самой сцене видны IP, имя и задержка выбранного узла; на коротких маршрутах подписи находятся также под точками. Карточка следует за сигналом, наведение показывает другой узел, щелчок закрепляет его (повторный снимает закрепление). Выбрать узел можно и кнопкой в полном списке, в том числе с клавиатуры. Горизонтальной прокрутки нет. Полный список узлов доступен под сценой. [Пример маршрута на тестовых данных](screenshots/network-route-desktop.png).

Трассировка ограничена 24 узлами и примерно 30 секундами. В Docker утилита уже установлена; при запуске из исходников установите системный пакет `traceroute`. Дополнительные привилегии не нужны. Измеряется маршрут от worker, а не от посетителя; UDP-путь может отличаться от HTTPS. Пропуски помечаются `*` и не меняют статус сайта. Обратное движение сигнала условное: обратный маршрут не измеряется. Маршруты и внутренние IP доступны только владельцу; на публичной странице остаётся карта HTTP-проверок.

Результат считается устаревшим после трёх интервалов без нового измерения: при интервале 10 минут — через 30 минут. Тогда появляются «Нет актуальных данных», «Ожидает обновления» и сообщение о просроченных проверках. Сам опрос по-прежнему выполняется через один интервал. Ошибки и отсутствие результатов видны сразу.

Домены в основной таблице можно перетаскивать мышью за маркер слева. С клавиатуры — фокус на маркере и **Alt + ↑ / ↓**. Порядок сохраняется для рабочего пространства и восстанавливается после обновления страницы; избранные остаются сверху, перестановка доступна внутри своей группы. При активном фильтре скрытые домены сохраняют свои места. Если сервер не подтвердил сохранение, таблица возвращается к прежнему порядку и показывает сообщение.

Кнопки с пиктограммами в верхней панели позволяют добавлять и проверять домены, обновлять страницу и включать автообновление. Названия видны в подсказках. Общая панель кнопок остаётся на тех же местах в настройках и других закрытых разделах; кнопка сигналов возвращает к визуализации на главной. На страницах форм автообновление недоступно, чтобы не сбрасывать ввод. В строках списка есть значки изменения, ручной проверки и приостановки/возобновления. Проверка и пауза сохраняют выбранные поиск, фильтр и период. В карточке домена сверху находятся изменение, проверка, приостановка и удаление; удаление требует текстового подтверждения.

Ручная проверка сохраняет свежие результаты, но не отправляет сообщения в Telegram. Worker оценивает сохранённое состояние на следующем цикле. В веб-процессе одновременно выполняется одна ручная проверка; стандартный тайм-аут на домен — 120 секунд.

### Прокси VirusTotal

В **Настройках → VirusTotal** включите галочку **Использовать прокси для VirusTotal**: появится поле адреса HTTP(S)- или SOCKS5-прокси. При снятии галочки адрес и данные доступа сохраняются, а VirusTotal возвращается к обычному подключению. Он применяется только к запросам VirusTotal: HTTP-проверки сайтов и Telegram используют собственные настройки. Пустое поле сохраняет прежнее значение; отдельная галочка удаляет сохранённый прокси. Приоритет: `VIRUSTOTAL_PROXY` в окружении → `malware.vt_proxy` в YAML → сохранённое значение. Без отдельного прокси используется общий HTTP-клиент. Worker и веб-проверки читают настройку заново при каждом запуске. [Поле прокси в панели](screenshots/virustotal-proxy-settings.png).

Прокси хранится рядом с базой в `<имя-базы>.virustotal-proxy` с правами `0600`; сохранённый адрес вместе с учётными данными виден в настройках владельца после обновления страницы. Файл и временные файлы исключены из Git и Docker-контекста. Включайте их в защищённую резервную копию.

В Docker адрес `127.0.0.1` указывает на сам контейнер. Для прокси, доступного только через localhost Linux-хоста, предусмотрен дополнительный файл `compose.host-network.yaml`:

```bash
docker compose -f compose.yaml -f compose.host-network.yaml config --quiet
docker compose -f compose.yaml -f compose.host-network.yaml up -d --build
```

Этот вариант подключает web и worker к сети хоста и оставляет панель на `127.0.0.1:${SITEWATCHER_PORT:-8080}`. Проброс портов удаляется; сеть хоста используется только при явном выборе этого файла. Чтобы запомнить выбор для обычных команд Compose, скопируйте файл в локальный `compose.override.yaml` (исключён из Git). Для возврата к стандартной сети уберите локальный override и выполните `docker compose -f compose.yaml up -d`. Формат `!reset` описан в [документации Compose](https://docs.docker.com/reference/compose-file/merge/); особенности сети хоста — в [Docker Docs](https://docs.docker.com/engine/network/drivers/host/).

Вместо host-network можно использовать прокси с адресом, который доступен из стандартной сети контейнера. HTTPS-проверка сертификатов прокси и VirusTotal остаётся включённой.

Ошибки сети/прокси, отказ API-ключа, лимит запросов и сбой сервиса показываются раздельно. HTTP 404 означает отсутствие готового отчёта, а не чистый результат. Эти случаи остаются неопределённым результатом; сайт автоматически на сканирование не отправляется. Описание кодов API: [VirusTotal Errors](https://docs.virustotal.com/reference/errors).

### Настройки

Английский язык включён по умолчанию; русский выбирается в настройках. Выбор сохраняется для учётной записи и страницы входа. Публичная страница использует язык владельца. Диагностика внешних сервисов и идентификаторы API/CSV могут оставаться на исходном языке.

Часовой пояс по умолчанию — `Europe/Moscow`; время хранится в UTC. В списке доменов последняя проверка отображается компактно: `2026-11-03 15:46`. Переключатель светлой и тёмной темы запоминает выбор и с JavaScript сохраняет незаполненные формы.

Адрес сайта можно вводить как `site.ru`, `http://site.ru` или `https://site.ru`, в том числе с каталогом: `site.ru/catalog/`. Без протокола используется HTTPS. Проверки доступности, ключевых слов и подмены страницы обращаются к заданному адресу; DNS, сертификат, регистрация, РКН и трассировка используют имя хоста. В редактировании HTTP/HTTPS выбирается слева от поля с доменом и каталогом. Можно изменить домен: история, избранное, порядок и настройки сохраняются; кэш прежнего хоста и сетевой маршрут не переносятся. Старые результаты остаются историей, а новый домен ожидает свежую проверку. Одна запись соответствует одному имени домена. Адрес сохраняется при CSV-экспорте и импорте. [Редактирование адреса на телефоне](screenshots/domain-address-edit-mobile.png).

Интервал проверки заранее заполнен. Унаследованные параметры показываются как `Default` с текущим значением. Ключевые слова задаются через запятую; фразы с запятыми заключайте в кавычки. TCP-порты принимают числа и диапазоны, например `1-1024, 2205`. Пустое поле наследует общий список, `-` очищает его. Индивидуальные параметры оставшихся портов сохраняются.

Изменение `interval_minutes` у домена задаёт интервал для всех его проверок; `0` останавливает расписание. Без переопределения действуют интервалы `schedules.<check>.interval_minutes`. Планировщик просыпается каждую минуту; увеличение `scheduler.interval_minutes` уменьшает точность расписания. Ручные проверки могут использовать кэш согласно `cache_ttl_minutes`, плановые выполняются заново, когда наступает срок.

Панель отклоняет устаревшие правки при одновременном редактировании. Пароли прокси повторно не показываются. Удаление индивидуального HTTP-прокси возвращает домен к общему клиенту, у которого может быть собственный прокси. CSV-экспорт содержит переопределения и может содержать учётные данные прокси — храните его как секрет. Импорт проверяет строки и сообщает об ошибках; замена затрагивает только перечисленные домены.

## Telegram и прокси

Telegram необязателен. В **Настройках → Дополнительные настройки**:

1. Сохраните токен, полученный у BotFather.
2. При необходимости сохраните прокси.
3. Откройте бота, отправьте `/start`, затем нажмите «Найти чаты» в панели.
4. Сохраните получателя и отправьте тестовое уведомление.

Обычное сохранение настроек не отправляет сообщение. Поиск чатов не забирает обновления; webhook или работающий polling могут мешать поиску. В этом случае можно указать числовой ID чата вручную.

Поддерживаются HTTP, HTTPS, SOCKS5 и ссылки Telegram SOCKS:

```text
http://proxy.example:8080
https://proxy.example:8443
socks5://proxy.example:1080
https://t.me/socks?server=proxy.example&port=1080
tg://socks?server=proxy.example&port=1080
```

Авторизация поддерживается через `user:password@` в URL или параметры `user` и `pass` в ссылке Telegram. Спецсимволы кодируйте как компоненты URL. Ссылки преобразуются локально, без открытия `t.me`. `socks5h` также принимается. MTProto-ссылки `t.me/proxy` с `secret` не поддерживаются: бот использует HTTPS Bot API, для MTProto нужен другой клиент.

Сохранённые токен и прокси находятся рядом с базой в файлах `<имя-базы>.telegram-token` и `<имя-базы>.telegram-proxy` с правами `0600`. Поля не показывают сохранённые секреты; пустое поле оставляет значение, отдельное действие удаляет прокси. Файлы исключены из Git и Docker build context. Включайте их в защищённую резервную копию.

Непустые `TELEGRAM_TOKEN` и `TELEGRAM_PROXY` в окружении имеют приоритет над сохранёнными значениями. Если отдельный прокси Telegram не задан, HTTPX сохраняет стандартное поведение переменных окружения прокси, включая `HTTPS_PROXY` и `ALL_PROXY`. Удаление сохранённого прокси не отключает эти переменные.

Worker перечитывает токен и прокси между циклами. После их изменения перезапустите работающий polling-бот. Подключение панели, команды бота и отправка уведомлений используют одну настройку прокси. Для HTTP-проверок сайтов отдельно используется `http.proxy` в YAML или переопределение домена.

Получатель уведомлений выбирается в порядке: `alerts.chat_id` в YAML, сохранённый чат владельца, `TELEGRAM_ALERT_CHAT_ID`. Смена получателя не меняет владельца доменов и истории. Пустой `TELEGRAM_ALLOWED_USER_IDS` разрешает доступ всем; для закрытого бота укажите разрешённые положительные ID через запятую.

## Проверки РКН и внешние сервисы

РКН разделён на две независимые проверки:

- **Блокировка домена** (`rkn_domain`): критическая ошибка при записи домена или его родительского домена в базе.
- **IP в реестре** (`rkn_ip`): предупреждение при записи IPv4, полученного через DNS. IP может принадлежать общему хостингу.

Эти результаты отражают списки источников, а не доступность сайта у конкретного провайдера. IPv6 здесь не проверяется.

Основной источник — [Antifilter](https://antifilter.download/): `domains.lst`, `ip.lst` и `subnet.lst` из `/list/`. Резервный — [bol-van/rulist](https://github.com/bol-van/rulist): `reestr_hostname.txt`, `reestr_ipban4.txt` и `reestr_resolved_ip4.txt` из одного зафиксированного коммита. Используются точные IPv4 и CIDR, без приблизительных сводок `/24`. Неполный, устаревший или недоступный основной набор заменяется резервным целиком.

Обновление индекса задаёт `rkn.cache_ttl_hours` — по умолчанию 12 часов. Максимальный возраст исходных файлов задаёт `rkn.max_source_age_hours` — по умолчанию 168 часов. У Antifilter берётся самая старая дата `Last-Modified` компонентов, у bol-van — самая старая дата изменения трёх файлов на выбранном коммите. Новый посторонний коммит не делает старые списки свежими. Отсутствующие, будущие и просроченные даты не позволяют подтвердить отсутствие записи. Если оба источника не прошли проверку, прежний индекс сохраняется, а результат становится неопределённым.

Старые `checks.rkn_block` и `schedules.rkn_block` задают обе проверки, если новые ключи не указаны явно. `rkn.check_ip: false` выключает проверку IP глобально. Старые объединённые результаты остаются в истории, но не участвуют в текущем статусе, кэше, уведомлениях и расписании. CSV принимает прежний формат. `rkn.source: z-i` и `rkn.z_i_url` принимаются для совместимости, но Zapret-Info больше не запрашивается; старый индекс перестраивается автоматически.

Для VirusTotal включите проверку malware у домена и сохраните API-ключ в **Настройках → VirusTotal**. Ключ скрыт по умолчанию. Значок глаза показывает действующий ключ по отдельному авторизованному запросу и скрывает его повторным нажатием. Просмотр не сохраняет ключ заново; изменение поля явно заменяет его. [Пример поля](screenshots/virustotal-key-settings.png). Пустое поле оставляет сохранённый ключ, отдельная галочка удаляет его. Ключ хранится рядом с базой в `<имя-базы>.virustotal-key` с правами `0600` и применяется при следующей проверке без перезапуска процессов. Приоритет: непустой `VIRUSTOTAL_API_KEY` в окружении, затем `malware.vt_api_key` в YAML, затем ключ из панели. Эти файлы содержат секреты; включайте их в защищённую резервную копию. Лимиты запросов настраиваются в YAML. Если отчёта нет, проверка отправляет `https://<домен>/` на анализ в VirusTotal. До готовности отчёта показывается «Проверяется»; это не повышает общий статус и не включается в краткую сводку проблем Telegram. Ошибки настройки и обращения к сервису по-прежнему требуют внимания. GET и POST учитываются отдельно в лимитере. Повторная отправка того же URL для одного владельца блокируется на 24 часа, в том числе после перезапуска; следующее получение отчёта выполняется при плановом или ручном опросе. UNKNOWN по умолчанию не берётся из кэша malware. Отправленный URL попадает в базу VirusTotal; учётные данные и тексты диагностики не отправляются. Ошибки авторизации и квот не запускают анализ вместо отсутствующего отчёта. WHOIS/RDAP использует общую базу; для поддерживаемых российских зон доступен fallback на порт 43. DNSBL зависит от ответов DNS, ошибки запросов дают неопределённый результат. Базовая точка проверки смены IP хранится в основной базе отдельно для каждого владельца и разовых проверок. При переносе старой отдельной базы задайте `ipchange.db_path`: данные копируются один раз для каждой области без изменения исходника. Иначе первый запуск создаст новую точку отсчёта.

Проверка чёрных списков IP при включении использует **DroneBL, Blocklist.de и PSBL**.
Список можно заменить через `ipbl.zones` в YAML; явный `zones: []` оставляет проверку
без источников. Перед запросами каждый источник проходит положительный (`127.0.0.2`)
и отрицательный (`127.0.0.1`) контроль. Сбой контроля, таймаут, неизвестный код ответа
или отказ в доступе считаются отказом источника, а не попаданием в список. Если хотя
бы один исправный источник проверил все IPv4 и не нашёл попаданий, результат — OK;
отказы остальных отмечаются нейтральным сообщением о неполном покрытии. Когда ни
один источник не завершил проверку, результат — UNKNOWN.
Подтверждённое попадание остаётся CRIT даже при отказе другого источника; неполное
покрытие, коды ответов и ошибки сохраняются в метриках. Проверяется репутация IPv4;
параметр `check_ipv6` учитывает наличие AAAA, но не включает проверку репутации IPv6.
Spamhaus ZEN требует подходящих условий доступа и не работает через публичные
резолверы без отдельной настройки. SpamCop можно добавить после проверки из своего
окружения. Старые результаты и результаты с другим набором источников/резолверов
автоматически перепроверяются без ожидания суточного интервала. UNKNOWN по умолчанию
не берётся из кэша; явное исключение — `schedules.ip_blacklist.cache_unknown: true`.

## Учётная запись и публичная страница

`sitewatcher setup` создаёт локального владельца. Нужен терминал со скрытым вводом; пароль — от 8 символов с проверками Django. Публичной регистрации и сброса через почту нет. Обычный вход действует 12 часов. Галочка «Запомнить меня на 30 дней» сохраняет вход в этом браузере на 30 дней; она выключена по умолчанию. Выход отзывает эту сессию, смена или сброс пароля — сессии в других браузерах.

Без `--owner` создаётся новая учётная запись мониторинга без присвоения существующей истории Telegram. Для намеренной привязки первой учётной записи используйте `sitewatcher setup --owner <owner_id>`. Повторная настройка не создаёт второго владельца и не меняет привязку. Параметр `web --owner` лишь проверяет существующую привязку, а не открывает чужие данные.

Для восстановления доступа выполните на сервере `sitewatcher password`. Команда меняет пароль, снимает блокировку входа и завершает прежние сессии, сохраняя данные мониторинга. При смене пароля в панели текущая сессия остаётся, остальные завершаются. Сессия действует 12 часов; после пяти неудач пара «имя пользователя/адрес клиента» блокируется на 15 минут. Заголовки с пересланным адресом клиента игнорируются.

В **Настройки → Status pages** создавайте отдельные страницы состояния. Для каждой задайте заголовок, выберите домены и доступ: **Публичная** открывается всем по обычному адресу, **Приватная ссылка** — любому обладателю ссылки. У публичной страницы можно задать часть адреса после `/`, например `shop-health`; смена адреса отключает прежнюю ссылку. Новые приватные ссылки можно открывать и копировать в списке Status pages и редакторе. Для ранее выданных ссылок потребуется однократный перевыпуск, чтобы показать адрес в списке; до этого старые ссылки продолжают работать. Перевыпуск отзывает предыдущую ссылку. Отключение страницы закрывает все её адреса, удаление не затрагивает домены и историю мониторинга. Существующая страница и ранее выданные ссылки сохраняются после обновления. Страница показывает выбранные сайты и безопасные результаты проверок; закрытые домены, диагностические сообщения и внутренние маршруты не публикуются.

Публичные домены отображаются компактным списком с колонками состояния, истории, доли успешных проверок и времени последней проверки. Нажатие на строку раскрывает проверки и график вместе; список работает и без JavaScript. Зелёный статус «Доступен» относится только к HTTP, замечания остальных проверок отмечаются отдельно. Примеры: [компьютер](screenshots/public-unified-desktop.png), [телефон](screenshots/public-unified-mobile.png), [раскрытие](screenshots/public-inline-details.png).

Верхняя панель публичной страницы использует те же кнопки-пиктограммы с подсказками: карта и обновление; автообновление всегда включено. Сводка и время последнего результата расположены рядом с логотипом, как в кабинете; выбор периода находится в заголовке списка. Кнопка сигнала включает ту же визуальную карту: медленный обмен, паузу, скорость, повтор, полный экран и закрепление сайта. В ней видны только опубликованные домены и все типы их проверок; диагностические сообщения и закрытые сайты не передаются гостю. На широком экране консоль находится слева на фоне карты, сервер — в центре, карточки доменов — справа. В записи видны время, тип проверки, домен, результат и длительность. Полноэкранный режим использует высоту окна; на узком экране журнал располагается над картой. При ручной прокрутке автопереход к последним событиям останавливается; кнопка «К последним событиям» возвращает его. Карта и консоль обновляются раз в две секунды. Изменение списка публикации учитывается при следующем опросе, а отключение публикации или отзыв дополнительной секретной ссылки очищает соответствующую карту. Включение запоминается отдельно от закрытой панели. [Карта на компьютере](screenshots/public-map-desktop.png), [на телефоне](screenshots/public-map-mobile.png).

В раскрытии каждого домена показаны все включённые проверки: последний статус, время результата и отметка просрочки. Без результата статус UNKNOWN. По умолчанию страница тёмная; сохранённый выбор посетителя имеет приоритет.

Ссылка открывает статусы проверок и HTTP-данные выбранных доменов: историю, время ответа, состояние свежести/паузы и события выполнения проверок. ID владельца, приватные домены, диагностические сообщения, сырые метрики и управление недоступны. Добавьте `data` к ссылке для JSON. Для дополнительной секретной ссылки хранится только SHA-256 токена; ответы запрещают кэширование, индексацию и передачу referrer. При утечке перевыпустите ссылку. Reverse proxy должен отключать или скрывать журналирование `/status/`.

Автообновление всегда включено на панели мониторинга и публичной странице. Оно сохраняет открытые домены, прокрутку и фокус, в том числе после смены периода и фильтров. Чтение раскрытого домена не останавливает обновление; ввод в поле, несохранённый текст и перетаскивание откладывают его. Состояние разделено по учётной записи/странице или адресу публикации.

## Эксплуатация и восстановление

На одну базу нужен **один веб-процесс и один планировщик**. Обычный `sitewatcher bot` уже содержит планировщик: остановите worker или запустите бот с `--no-scheduler`. Общая блокировка защищает от одновременного запуска планировщиков и освобождается после остановки или аварии.

Worker выполняет проверки и очистку истории без Telegram. При настроенном Telegram он также отправляет уведомления. Ошибка доставки сохраняет ожидающее уведомление до следующего цикла. Ухудшение и восстановление обходят интервал повторных сообщений; одинаковая серьёзность соблюдает cooldown. Неудачная или отсутствующая проверка не считается успешной; восстановление требует свежих результатов включённых проверок.

Очистка выполняется раз в сутки по UTC с догоняющим запуском при старте. Настроенные сроки хранения и воскресная оптимизация сохраняются. Ctrl-C и SIGTERM корректно закрывают ресурсы.

`/healthz` проверяет читаемость базы и схемы, а не активность worker или здоровье сайтов. Время последней проверки описывает сохранённое наблюдение. Автообновление панели и публичной страницы выполняется раз в минуту и приостанавливается при редактировании фильтра или открытой подсказке. Формы редактирования и входа не обновляются автоматически.

Режим `sitewatcher web --read-only` запрещает изменения мониторинга и предпочтений. Смена пароля, сессии и учёт попыток входа продолжают писать в базу; просмотр истории, CSV-экспорт и смена темы доступны.

По умолчанию сервер слушает `127.0.0.1`. Для доступа к удалённой установке можно открыть туннель:

```bash
ssh -N -L 8080:127.0.0.1:8080 your-server
```

Панель доступна по тому же локальному адресу и требует входа. Порт `0` выбирает свободный порт и выводит адрес. Формы защищены сессиями и CSRF, повторяющиеся поля и запросы больше 1 МиБ отклоняются.

Для HTTPS за доверенным reverse proxy задайте конкретные `SITEWATCHER_WEB_ALLOWED_HOSTS`, включите `SITEWATCHER_WEB_HTTPS=1` и только при перезаписи `X-Forwarded-Proto` прокси включите `SITEWATCHER_WEB_TRUST_PROXY=1`. Не публикуйте порт приложения напрямую. `SITEWATCHER_WEB_BIND=0.0.0.0` используется внутри контейнера; Compose оставляет порт хоста локальным.

Перед обновлением сохраните SQLite, YAML, `.env` и приватные файлы `.web-secret`, `.telegram-token`, `.telegram-proxy`, `.virustotal-key`, `.virustotal-proxy`, `.virustotal-proxy-enabled`. Индекс РКН можно восстановить. Миграции добавляют поля без удаления истории; сохранение веб-ключа оставляет сессии действительными после перезапуска. Подробности: [эксплуатация и восстановление](operations.md), [проверка выпуска](verification-owner-public-dashboard-2026-10-22.md).

### Обновление установки Docker

Сначала сделайте резервную копию. Если устанавливали через Git, в каталоге проекта выполните:

```bash
git pull --ff-only
docker compose up -d --build
```

Если скачивали ZIP, распакуйте свежую версию и скопируйте её содержимое в ту же папку проекта, сохранив локальные настройки и файлы данных. Не меняйте имя папки: от него зависит выбор Docker-тома. Затем выполните `docker compose up -d --build`.

Для существующей установки не нужно повторять `setup`. После обновления проверьте вход, историю одного сайта и появление новой плановой проверки. Если выбран локальный `compose.override.yaml`, Compose продолжит использовать его.

### Запуск через systemd

Пример для установки в `/opt/sitewatcher` с абсолютным `DATABASE_PATH` в окружении службы:

```ini
[Unit]
Description=SiteWatcher monitoring worker
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=sitewatcher
WorkingDirectory=/opt/sitewatcher
ExecStart=/opt/sitewatcher/.venv/bin/sitewatcher worker
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Веб-панель запускается отдельной службой. Проверкам внешних сервисов нужен доступ к сети; ping может требовать разрешений ICMP.

## Командная строка и диагностика

```bash
sitewatcher scan example.com --only http_basic,tls_cert
sitewatcher check_domain example.com --owner 123456789 --force
sitewatcher check_all --owner 123456789
sitewatcher doctor
sitewatcher doctor --json
```

`scan` не добавляет домен, не сохраняет историю мониторинга и не отправляет уведомления; отдельные проверки могут вести собственный кэш. `check_domain` и `check_all` сохраняют результаты. Любая команда принимает `--config path/to/config.yaml`.

`doctor` проверяет конфигурацию, схему, целостность SQLite и права без создания базы и сетевых запросов. Код `0` означает готовность, `1` — необходимость исправлений. JSON содержит признаки наличия секретов, а не значения. Отсутствующая база с доступным для записи каталогом допустима для новой установки. Отчёты используют до 120 непустых временных интервалов; пробелы остаются неопределёнными. Кэш отчётов ограничен 8 записями, 4 МиБ и 60 секундами.

## Разработка

Сначала создайте виртуальное окружение, как описано выше, затем установите инструменты:

```bash
pip install -e '.[dev]'
ruff check sitewatcher tests
pytest
node --check sitewatcher/webapp/static/sitewatcher/theme.js
node tests/test_web_controls.cjs
node --check sitewatcher/webapp/static/sitewatcher/activity.js
node tests/test_live_activity.cjs
node tests/test_route_view.cjs
node --check sitewatcher/webapp/static/sitewatcher/key_visibility.js
node tests/test_key_visibility.cjs
python -m sitewatcher.main --help
docker compose config --quiet
```

GitHub Actions проверяет Python 3.12, 3.13 и 3.14, JavaScript, сборку пакета и контейнер без root. Тесты используют временные базы, подставные ответы и локальные тестовые серверы; настоящий Telegram-токен и внешние подключения не нужны.

Для цветных журналов доступен `pip install -e '.[rich]'` и `logging.pretty.use_rich: true` в YAML.

Переводы находятся в `sitewatcher/webapp/locale/ru/LC_MESSAGES/django.po`. После правок выполните `python -m django compilemessages -l ru`. GNU gettext нужен только для обновления каталогов; готовый `.mo` включён в пакет и контейнер.

На публичной странице время обновления страницы отделено от времени сохранённых проверок сайта. Сначала показано, сколько времени прошло после проверки, затем точная местная дата без часового пояса. «Успешные проверки» относятся к выбранному периоду и не означают непрерывный аптайм. Легенда истории различает недоступность, неизвестный результат и отсутствие измерений. Над графиком показана компактная строка «среднее» и три числа: за последние 15 минут, 1 час и 1 день. Период виден при наведении, фокусе клавиатуры или нажатии на число. Эти окна не зависят от выбранного периода графика; наведите курсор, коснитесь графика или используйте клавиши со стрелками для просмотра усреднённых точек. Если готового отчёта URL в VirusTotal нет, включённая проверка отправляет главную страницу на анализ и показывает ожидание отчёта.

## Группы сайтов

Сайты можно объединить в группы. «Основная» доступна всегда, в ней находятся
существующие сайты и адреса без выбранной группы. Если группа одна, список выглядит
как обычная таблица. При нескольких группах заголовок каждой группы раскрывает
и сворачивает её сайты; счётчики проблем видны и в свёрнутом виде. Поиск и фильтры
работают по всем группам, состояние раскрытия запоминается отдельно для владельца
и браузера. Глобальных кнопок сворачивания и флажков выбора в списке нет.

При добавлении или редактировании домена выберите существующую группу либо «Новая»
и введите название. Новая группа создаётся только вместе с успешным сохранением
домена; ошибки и отмена формы не оставляют пустых групп. При добавлении нескольких
адресов группа применяется ко всем. Старая форма не может отменить более поздний
перенос: при конфликте обновите форму.

Перетаскивайте домен за ручку слева на заголовок или сайт другой группы, включая
пустую или свёрнутую группу. После подтверждения сохранения группа назначения
раскроется. При ошибке подтверждения обновите страницу, чтобы проверить сохранённое
состояние. Избранное и ручной порядок действуют внутри группы. Перенос также
доступен через редактирование домена. Управление группами находится в настройках;
удаление группы возвращает сайты в «Основную», сохраняя настройки и историю.

В создании и редактировании статусной страницы можно отметить одну или несколько
групп. Публикуется их актуальный состав, включая будущие добавления; отдельные сайты
можно выбрать дополнительно. Только выбранные группы могут раскрывать свои названия
на публичной странице. Существующие страницы без выбранных групп сохраняют прежний
набор сайтов. Перенос сайта меняет видимость на страницах, привязанных к группам.

График ответа показывается, только если HTTP-проверка включена и в выбранном периоде
есть HTTP-наблюдения. Если их нет, раздел графика скрыт; остальные проверки доступны.
Неуспешные HTTP-наблюдения не скрывают раздел.
